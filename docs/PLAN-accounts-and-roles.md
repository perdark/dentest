# خطة: حسابات الأطباء والصلاحيات — تمهيداً للأونلاين

**الحالة:** مسودّة للمراجعة. لا يُنفَّذ منها شيء بلا قرار المالك.
**كُتبت:** 2026-08-27 · **القرار المرتبط:** حذف الأطباء نُفِّذ (الجزء الآمن).

---

## 1. أين نحن الآن

```
رمز واحد (PIN) للعيادة كلها        ← ماكو حسابات
جدول doctors = بيانات محاسبية      ← مو حسابات دخول
isOwner = بوليان، مستعمل بـ12 موضع  ← كل الصلاحيات
الحماية = الوصول الفيزيائي للجهاز   ← موثّقة بـscripts/reset-pin.ts
```

الأمان كله يقوم على: **اللي يوصل اللابتوب يوصل الدفاتر**. هذا مقبول أوفلاين،
و**ينهار تماماً** أونلاين.

---

## 2. 🔴 القاعدة اللي تحكم كل شي بعدها

**أي صلاحية تُفرض بالواجهة فقط = ليست صلاحية.**

بتطبيق أونلاين، المتصفح يقدر يستدعي أي `server action` مباشرةً. إخفاء زر
لا يمنع أحداً من استدعاء الدالة وراه. لهذا:

> الفحص لازم يكون **بالخادم عند كل عملية**، والأفضل **بالقاعدة نفسها**.

في گراند ليان هذا منفَّذ بـRLS على Postgres (52 فحص). SQLite ما عنده RLS،
فأي شي نبنيه اليوم يبقى فحوصات بالخادم — تنفع أوفلاين، وتحتاج **إعادة كتابة**
لما ننتقل لـPostgres.

**⚠️ نتيجة عملية:** بناء نظام صلاحيات كامل الآن على SQLite هو شغل يُرمى.
الأفضل بناؤه **مع** نقلة الأونلاين، لا قبلها.

## 3. الأدوار المقترحة

| الدور | يشوف | ما يشوف |
|---|---|---|
| **المالك** | كل شي: صافي العيادة · كل الأطباء · الإعدادات · سجل التعديلات · النسخ | — |
| **طبيب** | حالاته · دفعاته · حصته · مواعيده · مستحقات مختبره | أطباء ثانيين · صافي العيادة · المصروفات · الإعدادات |
| **استقبال** | المواعيد · المرضى · تسجيل دفعة | أي صافي · نسب الأطباء · الحصائل · الإعدادات · سجل التعديلات |

**تأكيد مطلوب من العيادة:**
- هل الاستقبال يسجّل **دفعات**؟ (تسجيل الفلوس صلاحية حسّاسة)
- هل الطبيب يشوف **نسبته المئوية**، أو المبلغ النهائي بس؟
- هل الطبيب يشوف مرضى **الأطباء الثانيين**؟

## 4. تغييرات القاعدة (لما يجي الوقت)

```
users
  id · username · password_hash · role('owner'|'doctor'|'reception')
  doctor_id → doctors.id   (NULL للاستقبال والمالك غير الطبيب)
  is_active · created_at · last_login_at

sessions
  id · user_id · expires_at · user_agent · ip
```

**⚠️ `users` منفصل عن `doctors` عمداً:**
- طبيب موجود بالدفاتر وما عنده حساب دخول (الوضع الحالي لكل الأطباء)
- حساب استقبال ما يقابله طبيب
- إيقاف الدخول ≠ إيقاف الطبيب محاسبياً

دمجهما يعني إن حذف حساب يمس سجلات مالية — نفس الفخ اللي عالجناه بالحذف.

## 6. الترتيب المقترح

**المرحلة أ — أوفلاين (تنفع الآن، تبقى مفيدة بعدين)**
1. `users` + `sessions` + تجزئة كلمات المرور
2. تسجيل دخول باسم مستخدم بدل رمز مشترك
3. `requireRole()` بالخادم عند كل `server action`
4. إخفاء الواجهة **بعد** فرض الخادم لا قبله

**المرحلة ب — مع الأونلاين**
5. الانتقال لـPostgres
6. **RLS بالقاعدة** — الفحص ينتقل من الكود للقاعدة
7. سجل تدقيق يربط كل تعديل بمستخدم (اليوم `recordEdit` ما يعرف منو)

**⚠️ الخطوة 7 مهمة:** سجل التعديلات الحالي يسجّل **ماذا** تغيّر، مو **منو**
غيّره. بعيادة فيها موظف واحد هذا كافٍ؛ بفريق فهو ثغرة.

---

## 7. ما لا يجب عمله

- ❌ صلاحيات بالواجهة وحدها
- ❌ دمج `users` مع `doctors`
- ❌ بناء RLS-like بالكود على SQLite ثم إعادته على Postgres
- ❌ إضافة أدوار قبل ما تتأكد أدوار العيادة الحقيقية من المالكة
