# UX review + fixes — 2026-08-24

The audience is now explicit, and it changed the verdict on most screens:

- **Dr. Uday** — owner. Every dinar in the app is his money, each doctor has a different commission %
  and a different lab. He audits numbers, asks a lot, gives a lot of notes, and **his eyesight is weak**.
- **The secretary** — does the data entry, on the same laptop, often with him watching.

So small type, dimmed values, colour-only status and "open the record to see the note" were treated as
defects, not polish.

Verification for everything below: `npx tsc --noEmit` clean · `npm test` 37/37 · `npm run verify`
(D1–D9) 37/37 · `npm run e2e` 30/30. No money arithmetic, query, mutation or server action was touched.

---

## 1. Bugs the client reported

### 1.1 Column headers were not over their own numbers — every money table

`app/globals.css`. `.money` was styling the **box**, not the text:

```css
.money { … direction: ltr; display: inline-block; }   /* before */
```

That class sits on `<td>` as often as on `<span>` (68 call sites). On a table cell:

- `display: inline-block` **stops the cell being a table cell** — it drops out of the column grid, so
  the header above it no longer measures the same column;
- `direction: ltr` flips what `text-end` resolves to (right inside the LTR cell, left in the RTL
  `<th>`), pushing header and value to **opposite sides of the column**.

Now `.money` sets only `tabular-nums` + `unicode-bidi: isolate`. Fixed on التقويم · الأشعة · الديون ·
المصروفات · الحصيلة الشهرية · لوحة التحكم, verified by measuring the DOM, not by eye.

### 1.2 «ملاحظة» could not be clicked

It was a `<Badge>` — a decorative label. It announced that a note existed, never showed it, and could
not be opened. Now the **note text itself** renders in the cell (one truncated line), the row is a link
to the case, and the full text is on hover. The same treatment was applied to the daily ledger, where
`payments.note` was being returned by the query and shown on no screen at all.

### 1.3 24-hour time and spelled-out months

Times now read `2:30 م` / `8:00 ص`. Dates read `8/30`, or `8/30/2026` where no month header already
names the year. Storage is unchanged — DB stays `YYYY-MM-DD` and 24-hour `HH:MM`. Spelled-out
`30 آب 2026` survives only in prose: two page subtitles and three confirm-dialog sentences.

## 2. «عرض الأسبوع» — rebuilt

The old week view was a Google-Calendar time grid, 8am→8pm, ~1056px tall. But appointment time is
optional and in practice never filled: **all 111 appointments in `zuha.db` have `appt_time = NULL`**.
So it rendered a full screen of blank ruled lines and exiled every real appointment to a chip row
underneath it.

It is now a **7-column day agenda**: each day a column, each appointment a row with time (or «بلا وقت»),
patient name, doctor name, and status as a **word** in a badge. Columns cap their height and scroll
inside, so the week always fits one screen. The hour ruler, the lane math and the untimed chip row are
gone. It reads correctly whether or not the clinic ever starts entering times — the same week that
showed nothing now shows all 32 appointments.

The month view's per-day counts moved from 10px colour chips to `text-sm` chips that print the status
word (`3 حضر`, `2 لم يحضر`), with a legend that names each colour.

## 3. Legibility pass — what changed

Rules applied everywhere: `text-[10px]` banned · `text-xs` only for decorative labels, never a value ·
every value ≥ 14px, the decisive figure on a surface ≥ 16px bold · `text-muted-foreground` for labels
only, never to dim a value · status never by colour alone · icon-only buttons and row-opening links at
44px.

**Shared components** — cash-on-hand in the header is now the dominant element in its pill and names the
over-reserve state in words; `<MoneySummary>` (the "see the arithmetic before you save" line) is no
longer dimmed and its emphasised figure is 16px bold; all tables moved to a 16px base with 14px headers;
`<EmptyValue>`, badges, and dialog/sheet close buttons all raised.

**Settlement** — the lab-shortfall warning went from 10px to a bordered `text-sm` alert with an icon,
plus a summary alert above the table naming every affected doctor; «العمل المنجز» is un-dimmed; «الحصة»
is now a tinted, ruled, bold column instead of the eighth identical one; the clinic-net formula is
spelled out and a negative net says so in words instead of just turning red.

**Doctors** — «مستحقات العيادة» was ambiguous on a doctor's page (it can read as money the doctor owes
the clinic). Renamed **«المستحق للطبيب»** with an explicit subline, on both screens plus the tour, the
help page and the e2e assertion. Each doctor's payout is now a 2xl bold figure in its own block, the
commission % is visible per doctor, and the lab-tracking lines say plainly that they are never deducted.

**Lists** (implants · ortho · xrays · debts · patients · daily · cash · expenses · audit) — «المتبقي» is
the dominant column on every screen that has one; secondary columns collapse on narrow windows and stay
on desktop; missing phones use `<EmptyValue>` + icon instead of hiding at 60% opacity; patient balances
no longer use red (CONVENTIONS reserves it for genuinely negative amounts); audit's raw DB row id is
replaced by the amount the change moved, and its developer-English notes are now Arabic.

**Dashboard** — was seven identical stat cards. Now: النقد المتوفر alone as a hero figure, then «اليوم»,
then «هذا الشهر». X-ray income in the doctors table is marked by a background and an explicit
«لا يُضاف لأي طبيب», not by dimming a real number.

**Settings / tour** — all explanatory copy raised to 14px (it explains commission %, the lab formula and
salary mode — exactly what he interrogates), and the tour's buttons raised to 44px.

## 3b. The data-entry path — two money bugs, verified in the browser

The dialogs are where the secretary spends her day, and they hid two real defects:

1. **`xrays/xray-form.tsx` — the live total lied about `m`/`k` amounts.** The preview used a private
   digits-only helper instead of `parseAmount()`, so typing `12.5m` previewed **125 د.ع** while the
   server saved **12,500,000 د.ع**. The one screen where she checks the figure before saving showed a
   different figure than the one that got written. Now both sides use `parseAmount`. Verified live:
   `12.5m` → «المطلوب 12,500,000 د.ع».
2. **Enter in the x-ray patient-search box saved a zero-price film — and toasted success.** The search
   input sits inside the save form, `price` defaults to `""`, `parseAmount("")` is 0, and `recordXray`
   accepts 0. Enter is now suppressed on that field; the same trap in the daily entry dialog is guarded
   too. Verified live: the Enter handler prevents default.

Also fixed on that path: a bare one-click delete on lab entries (now a confirm naming the amount and
date); money state surviving a cancelled dialog, so the next patient's form opened pre-filled with the
previous one's figures (implants ×3, ortho, debts); حضر/لم يحضر failing silently with no message;
missing arithmetic on the expense form (now «رصيد الصندوق → الرصيد بعد المصروف», verified live);
phone fields without `type="tel"`/`dir="ltr"`; and errors shown as red text with no `role="alert"`.

Reported and deliberately **not** changed, because each needs a decision, not a fix:

- `lib/actions/ortho.ts` — `createOrthoCase` ends in `redirect()` and never returns `{ok:true}`, so its
  success toast is dead code. Fixing it means changing the server action.
- The daily entry dialog lets a case be opened at price 0. Making «السعر» required would block free /
  warranty cases — a clinic-policy question.
- `parseAmount` is lenient: `250k250k` silently parses as 250,000 rather than erroring. Preview and
  save agree, so nothing is lost today, but a typo passes silently.

## 4. Still open — decide with the client

1. **Booking granularity.** Does the clinic book by hour or by day? The agenda works either way, but if
   they book by hour the time field should become **required** in «حجز موعد». Right now it is optional
   and nobody fills it.
2. **Working hours** — never captured. Nothing depends on it now that the hour ruler is gone, but a
   day view could use it.
3. **Month headers** stay spelled-out («آب ٢٠٢٦»). Numeric would mean changing `formatPeriodAr`, which
   also feeds prose on cash, expenses, settlement, dashboard and audit. Easy to flip if he wants it.
4. **Demo data is dirty** — `zuha.db` contains junk rows from manual testing (e.g. a patient named
   `edrwsfv`). Run `npm run db:demo` before showing it to the clinic.
5. **Disk on the build laptop was at 99%** (967 MB free); Turbopack could not write its cache and
   crashed a browser test. Clearing this project's `.next` freed 1.9 GB. It needs a real cleanup —
   `~/Desktop/active/` is 11 GB.
